# atlas_mobile

Consumer mobile app for Project Atlas (Flutter 3 + Riverpod). See the root
[`README.md`](../README.md) for the full stack and the investor-demo flow.

## Prerequisites

- Flutter `>=3.24` / Dart `>=3.5 <4.0` (verified on Flutter 3.47.1 / Dart 3.13.1)
- **iOS:** Xcode + at least one simulator runtime (`xcodebuild -downloadPlatform iOS`)
- **Android:** JDK 17, Android SDK (platform 36, build-tools 36) and NDK 28.2
- CocoaPods (iOS pod install)

`flutter doctor` should report no issues before you start.

## Run

The app talks to the backend from `docker-compose.yaml`, so bring the stack up
first (`make dev` at the repo root) — otherwise registration and OTP calls fail.

```bash
flutter pub get
flutter run                 # pick a device when prompted
flutter run -d chrome       # fastest smoke test, no simulator needed
```

### API base URL

Defaults to `http://localhost:8000`, which is correct for the iOS simulator,
the Android emulator and Chrome. Override for a physical device on your LAN:

```bash
flutter run --dart-define=ATLAS_API_BASE_URL=http://192.168.x.x:8000
```

OTP codes are not sent by SMS in V0.5 — read them from Mailhog at
<http://localhost:8025>.

## Test

```bash
flutter analyze
flutter test
```

Widget tests run on the host Dart VM, so they need no simulator or emulator —
which is why CI runs `pub get` / `analyze` / `test` without a device.

If a test fails to load with a `shaders/ink_sparkle.frag` / SkSL error, the
build directory is stale: `flutter clean && flutter pub get`.

## Platform directories

`ios/`, `android/` and `web/` are generated by `flutter create` and are checked
in. Regenerate with:

```bash
flutter create --platforms=ios,android,web --org dev.atlas .
```

Bundle identifiers are `dev.atlas.atlasMobile` (iOS) and `dev.atlas.atlas_mobile`
(Android) — Flutter derives them differently per platform.
